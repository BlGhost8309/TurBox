## Предварительная совместимость с текущим OnlineTours

Старые первые пять запросов использовали дату 27.08.2026, которая к моменту теста уже прошла. Для сравнения создан отдельный ignored smoke-конфиг с теми же пятью городами, Турцией и датой 07.09.2026. Основной пользовательский конфиг не изменялся.


## Изменение `cheapest_date`

До патча после клика по минимальному проценту всегда выполнялись:

```text
sleep(4)
presence_of_element_located(body)
```

`body` уже присутствовал, поэтому проверка не подтверждала применение новой даты. Теперь код ждёт фактическое изменение tour URL с polling 0.1 секунды и прежним timeout 30 секунд. Если URL не изменился, запрос завершается диагностируемой ошибкой вместо продолжения со старым URL.

Добавлены отдельные логи времени появления кнопок процентов и изменения URL.

## P0.2 — классификация цены

P0.2 выполнен отдельной итерацией 29.08.2026.

### Реализованные состояния

- `PRICE` — price element распознан, а цена входит в настроенный диапазон;
- `NO_RESULTS` — показано явное сообщение OnlineTours об отсутствии предложений;
- `PRICE_PARSE_ERROR` — карточки туров загрузились без распознаваемой цены либо полезное состояние не появилось до timeout.

Цена вне `price_min` / `price_max` теперь считается промежуточным stale-state, а не готовым результатом. Это устраняет гонку после применения URL-фильтров.

Максимальный динамический timeout price-state увеличен с 12 до 45 секунд. Быстрые ответы не замедляются: wait завершается сразу при появлении одного из явных состояний.

Debug HTML теперь сохраняет начало `<body>`, а не первые 150000 символов `page_source`, занятые скриптами из `<head>`.
