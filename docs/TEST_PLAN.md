# TurBox Stage 1 — план проверки на рабочем ПК

> **Статус 22.08.2026:** базовая приёмка Stage 1 уже выполнена. Этот файл теперь является регрессионным чек-листом. Фактические результаты см. `TEST_RESULTS_2026-08-22.md`, дальнейший план — `NEXT_STEPS.md`.

Цель: повторно подтвердить рабочее поведение после будущих точечных изменений.

## Тест 0. Ничего не менять в конфиге

Перед первой проверкой **не редактируй Python-файлы**. Если текущие даты/поисковые условия уже неактуальны, можно изменить только обычный пользовательский конфиг, как ты делал раньше.

## Тест 1. Локальные проверки без сайтов — ОБЯЗАТЕЛЬНО

Запустить:

```text
run_stage1_checks.bat
```

Ожидается:

```text
[OK] ...
Ran 15 tests
OK
[OK] Stage 1 локальные проверки пройдены.
```

Допустимое предупреждение на текущем конфиге:

```text
[WARN] Повторяющиеся города: Екатеринбург
```

Если здесь FAIL — живые Selenium-тесты пока не запускать, прислать весь вывод окна.

## Тест 2. Быстрый OnlineTours smoke — рекомендую сначала его

Запустить:

```text
run_smoke_collection.bat
```

Он обработает только первый запрос из `url_generation_config.txt` и создаст отдельный `smoke_output/collection_urls_smoke.txt`. Основной `configs/collection_urls.txt` не меняется.

Если smoke прошёл, затем можно запустить привычный полный:

```text
run_collection_url_generator.bat
```

Проверить:

1. Chrome открылся.
2. OnlineTours начал обрабатывать запросы.
3. Город/страна/дата/ночи устанавливаются.
4. При `searchMinPriceData=true` выбирается дешёвая дата.
5. Фильтры цены/рейтинга/питания применяются.
6. `configs/collection_urls.txt` обновился/дополнился.
7. В нём блок выглядит как раньше:

```text
N. Город, Страна, ДАТА, ночей:X-Y, взрослых:2 (Новая дата ... | от PRICE | питание)
https://www.onlinetours.ru/...
```

### Что прислать после теста

- весь вывод консоли от запуска или хотя бы участок с первой ошибкой;
- новый `configs/collection_urls.txt`;
- если создан `debug_logs/debug_*` — его содержимое можно приложить архивом.

Не присылать пароль и cookies отдельно.

## Тест 3. Travelpayouts converter — после успешного Теста 2

Для smoke-файла просто запустить:

```text
run_smoke_link_converter.bat
```

Для полного обычного файла — привычный:

```text
run_collection_link_converter.bat
```

Проверить:

1. Открылся Travelpayouts.
2. Сработали существующие cookies либо login.
3. При капче старый ручной сценарий работает.
4. `sub_id` создаётся.
5. Появляется новый:

```text
postsCollections/collection_YYYY-MM-DD_HH-MM-SS.txt
```

6. Ссылка имеет партнёрский вид как в успешном результате от 19.08.2026.

### Что прислать

- консольный лог;
- новый `collection_*.txt`;
- если есть ошибка — `debug_logs/debug_collection_converter.log` и `debug_logs/debug_link_converter.log`.

## Тест 4. Hotel-mode generator — после обычной цепочки

Запустить:

```text
run_collection_url_generator_hotel.bat
```

Проверить:

- найдено название отеля;
- меняются города вылета;
- цены появляются там, где есть предложения;
- `NO_RESULTS` остаётся там, где предложений нет;
- создаётся `hotel_cities_*.txt`.

На текущем `departure_cities.txt` Екатеринбург присутствует два раза, поэтому ожидаемо может обрабатываться дважды. Это не ошибка Stage 1.

## Тест 5. Hotel-mode affiliate converter

Запустить:

```text
run_collection_link_converter_hotel.bat
```

Проверить новый `hotel_cities_PARTNERS_*.txt`.

## Критерий принятия Stage 1

Stage 1 считается подтверждённым, если:

- Тест 1 зелёный;
- обычный generator выдаёт корректный `collection_urls.txt`;
- обычный converter выдаёт партнёрские ссылки;
- hotel-mode generator/converter работают как до рефакторинга либо выявленная ошибка локализована в старом site-dependent Selenium-коде.

## Если упало

Главное — **не чинить методом тыка** до анализа лога. Прислать:

1. какой BAT запускался;
2. полный текст ошибки;
3. соответствующий входной файл;
4. debug log/pack;
5. что успел сделать Chrome перед ошибкой.

По этим данным следующая итерация должна быть точечной.
