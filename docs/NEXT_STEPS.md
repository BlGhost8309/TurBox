# TurBox — следующие шаги

Обновлено: 31.08.2026.

## 1. Проверить гостиничный режим

Следующий практический этап — короткая приёмочная проверка отдельного гостиничного сценария на реальных пользовательских данных:

1. Сформировать небольшой набор гостиничных запросов.
2. Запустить гостиничный сборщик только на этом наборе.
3. Проверить выходные записи и конвертацию партнёрских ссылок.
4. Если обнаружится ошибка, воспроизвести её на одном запросе и исправить адресно.

Полный массовый прогон обычного парсера для этого не требуется.

## 2. Наблюдать обычные рабочие запуски

Текущий обычный конвейер считается рабочим. Во время реального использования нужно обращать внимание на:

- `PRICE_PARSE_ERROR` и `REQUEST_ERROR` в итоговой сводке;
- повторяемость ошибки на конкретном запросе;
- корректность диапазона найденной цены;
- случаи `CHEAPEST_DATE_UNAVAILABLE` — они допустимы, если основная цена сохранена;
- отсутствие ручных пауз между запросами.

Диагностику следует начинать с одного проблемного запроса. Полный benchmark имеет смысл только после существенного изменения логики либо при признаках системной регрессии.

## 3. Возможные улучшения после появления реальной потребности

Это не обязательные работы ближайшего этапа:

- типизированные модели входного запроса и результата;
- структурированный JSON-выход наряду с текстовым форматом;
- выделение партнёрских ссылок в отдельный адаптер;
- дополнительная оценка качества гостиничных предложений.

## Критерии стабильной работы

- Каждый входной запрос получает цену или явный конечный статус.
- Один сбой не останавливает остальную очередь.
- Технические ошибки видны в сводке и коде завершения процесса.
- Найденная цена соответствует заданному диапазону.
- Конвертер пропускает служебные статусы и обрабатывает только полноценные URL.
- Для последовательной обработки не требуется вмешательство пользователя.
