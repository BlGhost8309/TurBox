## P0 — продолжить оптимизацию `collection_url_generator.py`

### P0.1. `cheapest_date`

Это главный измеренный bottleneck: 16.6–21.9 секунды на запрос в последнем smoke.

Нужно:

1. Найти внутри `get_min_price_date()` / связанного кода все `sleep`, длинные `WebDriverWait` и повторные поиски элементов.
2. Понять конкретный DOM-сигнал, когда блок процентов/дат действительно готов.
3. Ждать этот сигнал с коротким polling interval вместо фиксированного времени.
4. Не уменьшать timeout вслепую: быстрый ответ должен идти сразу, медленный должен иметь запас.
5. Сохранить существующий алгоритм выбора минимального процента.
6. Добавить/сохранить тайминг `cheapest_date`.
7. Проверить 5 запросов и сравнить с baseline 16.6–21.9 s.

Критерий: среднее время заметно уменьшилось, а найденные дата/URL/цена остаются корректными.

### P0.2. Отсутствующая цена

Ввести явное различие:

- `NO_RESULTS` — OnlineTours действительно показывает, что подходящих туров нет;
- `PRICE_PARSE_ERROR` — результаты есть, но код не смог считать цену;
- `PRICE` — цена успешно получена.

Использовать HTML/screenshot debug dump на проблемной странице, а не угадывать по одному отсутствующему XPath.

Проверить прежде всего Кисловодск и Ессентуки для Нижнего Новгорода/Перми/Самары.

## Чего сейчас НЕ делать

- не переходить на async/parallel Selenium;
- не добавлять Docker/PostgreSQL/Redis/Celery;
- не удалять `legacy/`, пока не завершена миграция;
- не менять одновременно parser и converter;
- не переписывать search config DSL в YAML просто ради архитектурной красоты;
- не исправлять `sub_id` в той же итерации с parser performance.
